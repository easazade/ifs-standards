# Permission

## Purpose

A `Permission` records allowance or authority granted by a user, organization, group, community, or other legitimate authority source to an actor. It permits a specific action within a defined scope.

Permissions can represent narrow actions such as `ACCESS_SYSTEM_DOCUMENTS` or broad special authority such as `ADMIN`, which means all allowed access within the given scope.

## IFS context and role

In IFS, sovereignty remains with individuals and affected collectives. A permission is therefore not permanent ownership of power. It is a scoped, auditable delegation that can be limited, reviewed, expired, or revoked.

The permission scope applies the IFS Scope Rule: authority only reaches the system, project, process, area, or other context where the grant is valid.

## Properties

| Property    | Type                | Required | Description                                                                                                         |
| ----------- | ------------------- | -------- | ------------------------------------------------------------------------------------------------------------------- |
| `id`        | `string`            | Yes      | Globally unique identifier for this permission.                                                                     |
| `ifsId`     | `string`            | Yes      | Stable IFS entity identifier. Value must be `com.ifs.entity.permission`.                                            |
| `name`      | `string`            | Yes      | Human-readable or machine-readable permission name, such as `ACCESS_SYSTEM_DOCUMENTS` or `ADMIN`.                   |
| `actorId`   | `string`            | Yes      | Identifier of the actor receiving this permission.                                                                  |
| `scopeId`   | `string`            | Yes      | Identifier of the scope object where this permission applies.                                                       |
| `scope`     | `object`            | Yes      | Scope object describing the system, project, process, area, or other bounded context where this permission applies. |
| `state`     | `string`            | Yes      | Lifecycle state. Values include `drafted`, `under-review`, `granted`, or `revoked`.                                 |
| `createdAt` | `string(date-time)` | Yes      | Timestamp when this permission record was created.                                                                  |
| `updatedAt` | `string(date-time)` | No       | Timestamp when this permission record was last updated.                                                             |
| `expiresAt` | `string(date-time)` | No       | Optional timestamp after which this permission no longer applies.                                                   |

## Required fields

- `id`
- `ifsId`
- `name`
- `actorId`
- `scopeId`
- `scope`
- `state`
- `createdAt`

## Relationships

- `actorId` can reference the actor receiving the permission.
- `scopeId` references the scope object where the permission is valid.
- `protocolIds` can reference Protocol entities that define permission rules, review rules, or revocation rules.
- `delegationEvidenceIds` can reference consent, vote, signature, or audit evidence records proving that the grant was legitimate.
